# Passagem de bastão — 31/07/2026

Estado do trabalho ao trocar de máquina. Tudo o que está descrito aqui já está
na `main` e no GitHub.

## Onde parou

A **tela de projetos** foi entregue em três fases, todas mescladas na `main`
(último commit `ac4526c`). Antes delas, três correções pontuais no fluxo de
edição.

### O que motivou tudo

O relato foi *"meu trabalho não fica salvo"*. Investigando, eram **quatro**
causas distintas, não uma. Três estão resolvidas:

1. **O passo de Cortes não relia o servidor ao voltar.** Era o único passo do
   wizard sem leitura no mount; o `RecordedWizard` monta um passo por vez, então
   sair para a Transcrição destruía o componente e voltar mostrava o painel
   vazio, com os sliders nos valores padrão, apesar de o `cuts.json` estar em
   disco. *(Rota `GET /jobs/{slug}/cuts` + leitura no mount.)*
2. **Reenviar um vídeo para um nome que já existia apagava o trabalho anterior
   em silêncio.** O campo de nome vinha preenchido com o slug atual, então
   reusar era o caminho de menor esforço. *(Invalidação no `stage_ingest`,
   guarda de 409 no upload, diálogo de colisão com três saídas, e sugestão de
   nome livre.)*
3. **Aplicar corte manual descartava transcrição, textos, sugestões e receita
   de render sem avisar.** O comportamento é intencional — o vídeo encurta e as
   legendas ficariam fora de sincronia — mas nada dizia isso. *(Confirmação
   antes, listando o que aquele projeto de fato tem.)*

A quarta continua aberta e está no topo das pendências abaixo.

### Fase 1 — listar e reabrir projetos

`GET /api/jobs`, tela de projetos, abrir projeto, guarda de sobrescrita no
upload (409) e diálogo de colisão.

Dois defeitos encontrados em revisão que valem conhecer, porque a mesma família
reapareceu depois: abrir um projeto pela lista caía no passo 1 com o `probe`
nulo e o "Próximo" travado (o `UploadStep` não carregava o job ao montar); e
"Substituir o vídeo" no diálogo enviava o nome que estivesse no campo, não o
projeto que o diálogo nomeava — dava para receber o aviso sobre `A1`, editar o
campo para `A2` e apagar o trabalho do `A2`.

### Fase 2 — título, excluir e liberar espaço

Título legível separado do slug, excluir projeto (mantendo o render exportado em
`output/`) e liberar espaço apagando só o `source.mp4`.

Precisou de **três rodadas** de correção depois da revisão final. As duas
primeiras introduziram problemas novos:

- o padrão `{slug}-part*` usado para limpar `input/` apagava as partes de um
  projeto vizinho — apagar `A1` destruía as de `A1-parte2`. Como "Liberar
  espaço" não apaga `input/`, num projeto já liberado essas partes eram a
  **última cópia do vídeo em resolução cheia**. Resolvido com casamento exato
  (`-part\d+\.[^.]+`);
- a guarda de sobrescrita falhava **aberta**: qualquer exceção ao montar o
  resumo do projeto virava "não existe projeto" e liberava o upload. Só fechou
  quando o `except` passou a devolver um `JobSummary(slug=slug)` em vez de
  `None` — proteger função por função não bastava.

### Fase 3 — os dois avisos do passo de Cortes

"Detectar pausas" desabilitado com explicação quando o vídeo original foi
apagado (mais 409 no backend), e confirmação antes do corte manual descartar o
trabalho.

Duas rodadas de correção, ambas com a **mesma raiz: um estado carregando dois
significados**. Primeiro `aPerder = []` significando ao mesmo tempo "sei que não
há nada" e "ainda não perguntei" — numa corrida entre `getJob` e `getCuts`, o
refino aplicava sem confirmação. Depois `aPerder = null` significando
"esperando" e "não consegui saber" — um `getJob` que falhasse travava o botão
para sempre, em silêncio. A versão final separa em `aPerder` + `carregandoJob`.

Vale reter o padrão: **distinga "sei que não" de "ainda não sei", e faça "ainda
não sei" falhar para o lado seguro.**

## O que falta

### 1. `stage_cut` não invalida os derivados — corrupção silenciosa (grave)

> **Resolvido em 2026-07-31** — spec em
> `docs/superpowers/specs/2026-07-31-stage-cut-invalida-derivados-design.md`,
> plano em `docs/superpowers/plans/2026-07-31-stage-cut-invalida-derivados.md`.

`pipeline/stages.py::stage_cut` reescreve o `trimmed.mp4` **sem apagar**
`transcript.json`, `edit-recipe.json`, `overlays.json` e `suggestions.json`.
Rodar "Detectar pausas" de novo num projeto que já tem transcrição deixa esses
arquivos apontando para a timeline antiga: o vídeo muda, as legendas não, e o
render sai fora de sincronia sem nenhum aviso.

É a quarta causa do "meu trabalho não fica salvo", e a pior das quatro: as
outras perdiam trabalho de forma anunciável; esta **corrompe em silêncio**.

O conserto tem dois lados, espelhando o que já existe:
- `stage_cut` invalida os derivados como o `stage_refine` já faz (a lista
  `DERIVADOS_DO_SOURCE` está em `pipeline/stages.py`);
- o `CutsStep` confirma antes, reaproveitando o mesmo aviso do corte manual —
  o estado `aPerder` já está montado e serve para os dois botões.

### 2. O projeto não tem logging

`import logging` não aparece em `api/` nem em `pipeline/`. Isso passou a
importar porque a fase 2 criou dois caminhos que engolem erro **por desenho**:

- `_tamanho_seguro`/`_mtime_seguro` devolvem 0 para qualquer `OSError`, então um
  arquivo sem permissão vira "0.0 MB" na lista — e "Libera 0.0 MB" num diálogo
  destrutivo cuja única justificativa é esse número;
- a limpeza das partes em `input/` é best-effort: uma parte travada fica órfã
  sem deixar rastro.

Os dois erram para o lado seguro, mas ninguém fica sabendo.

### 3. Disco: as partes de upload sobrevivem ao "Liberar espaço"

`create_job` grava os arquivos enviados em `input/<slug>-part*.mp4` e só o
*excluir projeto* os apaga. O "Liberar espaço" não — então o "Libera X MB"
subestima o que continua ocupando disco. Pelo mesmo motivo, o `bytes_total`
de cada projeto não conta essas partes e subdeclara o tamanho real.

### 4. Pendências menores, registradas em revisão

- Slug inexistente responde 409/200 em vez de 404: `get_state` não distingue
  "não existe" de "vazio", e `read_job` tem a mesma lacuna. Um nome digitado
  errado recebe uma explicação confiante e errada.
- `create_job` monta o caminho com o slug cru, sem `_job_dir_seguro` — assim
  como `orientation`, `caption-style` e `brand-kit`. Só os DELETEs e o
  `PUT /title` usam o guard. Não há bypass hoje (guarda e `init_job` concordam
  no caminho), mas o guard existe e deveria ser centralizado.
- `tem_trabalho()` é chamado fora do `try` em `create_job`: se levantar, vira
  500 em vez do 409 "com o melhor resumo que der". Falha fechado.
- O vocabulário do "o que se perde" está duplicado entre `CutsStep` e
  `ProjectsScreen`, com junções diferentes ("," vs "e") para a mesma lista.
- As flags `has_*` significam "arquivo existe", não "tem conteúdo": passar pelo
  passo Textos sem escrever nada grava `[]` e gera aviso de perda inexistente.
  Erra para o lado seguro.
- Acessibilidade dos diálogos: o `role="alertdialog"` não recebe foco, não
  prende foco e não fecha com Esc. Vale para os dois (colisão e exclusão).
- Nos testes do botão "Detectar pausas", dois dos três passam incidentalmente
  (o estado inicial já é o esperado).

## Como rodar

### Requisitos do repositório (valem em qualquer máquina)

- **`.env`** na raiz, a partir do `.env.example`, com `ELEVENLABS_API_KEY`. Sem
  a chave, `api/app.py` **recusa iniciar** — a não ser que você use
  `TTS_MODE=mock`, que mocka TTS e modo animado e deixa o fluxo de edição de
  gravação inteiro funcionando.
- **ffmpeg e ffprobe no PATH.** O pipeline de corte, junção e probe depende
  deles. Sem ffprobe, boa parte da suíte de `api/tests` falha.
- **Node** para o front e para o Remotion (`npx remotion render`).
- O servidor roda **sem `--reload`**: mudança em Python só vale depois de
  reiniciar, e mudança no front exige rebuild + copiar para `api/static/`.

### Subir

```bash
# backend + front servido em http://localhost:8000
python -m uvicorn api.app:app --host 127.0.0.1 --port 8000
```

Depois de mexer no front:

```bash
npm run build --prefix web
# copiar web/dist/* para api/static/, apagando os assets de hash antigo
# e reiniciar o uvicorn
```

### Testes

```bash
pytest -q                    # backend, da raiz
npm test --prefix web        # front
npx tsc --noEmit -p web/tsconfig.json
```

### Armadilhas específicas da máquina Windows onde isto foi feito

Podem não valer na máquina nova — verifique antes de assumir:

- `python3` não existe; era preciso usar `.venv/Scripts/python.exe`.
- `npm test` dentro de `web/` falhava nas 31 suítes com um erro de setup do
  vitest. O contorno era rodar da **raiz** com
  `web/node_modules/.bin/vitest.cmd run --root web`. Nessa forma, as duas suítes
  de paridade falham (leem caminho relativo ao cwd) — é o preço do contorno.
- Não havia `.env`, então tudo rodou com `TTS_MODE=mock`.
